The Problem

The current absence of a cohesive design system within our organization results in inconsistent user experiences, hindered design scalability, and increased development time

The team needed a robust design system and organized structure As the software became more complex and the team grew larger, the team started to face new challenges.

Our Solution

Made the Design system for the conceptual AI Automation platform. The primary goal of this project was to create a solid design system foundation that can be utilized during real production and subsequently handed off to the development team.

  • Objective: One system rigorous enough for Flow Builder's canvas but flexible enough for everyday screens, without becoming a bottleneck.
  • A full system from day one: tokens, components, documentation and governance.

Definition of Done

The task considered complete when the following criteria meets :

  • Visual Consistency: The design components adheres to the established visual guidelines, including colors, typography, spacing, and layout.
  • Guidelines: set of principles and instructions that ensure consistent and cohesive design across digital products and experiences.

The Investment Argument

  • Leadership and product first preferred a lighter, faster-to-ship system with fewer states and less documentation.
  • Flow Builder needed custom node types, a path-filtering variable selector, stateful toolbars, and zoom and pan controls. That made the case for the fuller system.
  • The two projects were built in parallel. Everyday screens tested the general system, and Flow Builder pushed it into harder problems.

Design system

Components

Anatomy of a component

  • Every component uses the same documentation structure: Brief, Live Usage, Copy Me block, states and variants matrix, and Behavior, Layout and Content guidance with right and wrong examples.
  • Accordion was among the first documented, with small, medium and large sizes, a live settings-screen example, and layout rules for the expand caret.
  • The same structure applies across the library, from Badges and Chips to Dropdowns (ten types, roughly two dozen state variants).
Design system

Governance

  • The whole team (designers, engineers, PMs) had Figma library access, with no gatekeeping.
  • Consistency came from a strict component and variant structure, plus a weekly design review that checked new or changed work before merging.
  • A running checklist tracked shipped states for each foundational piece (hover, disabled, keyboard support) so gaps were visible.
  • Design tokens were exported directly to CSS variables and JSON, so nothing was re-implemented by hand.

How a component ships

Proposed in the shared library→Checked against the checklist→Reviewed in weekly critique→Merged→Tokens exported to code

Design system

One system, many surfaces

Flow Builder

The contextual variable selector (a nested tree that filters variables by execution path) is built from the accordion and dropdown components. Canvas nodes (Apps, Logic, AI Skills) are documented components with default, filled, success and error states across default, hover and selected.

Human-in-the-Loop workspace

Uses list and table components for the claim review queue, and badges for AI confidence scores.

Outcome

Impact

  • Teams stopped rebuilding the same components, so new features shipped faster with less custom engineering.
  • Reuse let the Flow Builder team focus on hard problems (canvas tooling, the toolbar state machine) and not on basic forms and tables.
Reflection

Learnings

Governance beats gatekeeping

Open library access plus weekly reviews worked better than routing every change through one person.

Invest early

Committing to the fuller system before Flow Builder's complexity arrived avoided a rushed rebuild.

One source of truth

Exporting tokens to code kept design and engineering aligned better than a manual handoff.
